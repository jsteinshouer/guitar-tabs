On a desktop this app reads as restrained and coherent. On a phone or tablet on a stand — the scene PRODUCT.md names as governing — three separate defects stop the primary task cold.

## Design Specificity Verdict

**LLM assessment: category-interchangeable.** Swap "tab" for "recipe" or "snippet" and nothing here would need to change. The playing surface — the screen PRODUCT.md Principle 1 calls "the product" — is `<pre>{{ tab.content }}</pre>` and ten lines of CSS (`ui/src/views/Tab.vue:32,76-85`). No fret or string vocabulary, no tuning/capo line, no section awareness, no distinction between the tab grid and the chord lines above it.

The missed opportunity: the monospaced grid is a distinctive visual language this product already owns and has never used. Six string lines, dash runs, fret digits, `h/p/b/~` articulations, `|` bar dividers. Nothing on screen says "guitar" except a favicon and the word in the nav.

`ui/src/assets/_colors.scss:15-25` sets all ten `$primary-*` steps to the identical `#d0eb55`, collapsing the ramp so hover equals rest — then `custom.scss:77-83` overrides every button to `#a9bc52`, which is not the brand lime. The binding accent survives only on text links.

**Deterministic scan: 1 finding, a false positive.** `overused-font` at `ui/src/style.css:2` (`font-family: Inter`). That file is unreferenced Vite scaffolding — nothing in `ui/` imports it (verified by grep), `Inter` is never served, and its `#242424` background contradicts the `#393939` the app renders. The action is delete the dead file, not change the typeface. Assessment B confirmed by probe that `.vue` files are genuinely scanned, so the zeros across all twelve components are real. No color, typography, or whitespace rule fired anywhere — nothing in the scan challenges the lime, the dark surfaces, or the monospace alignment. The detector is regex-only on `.vue`/`.scss`; every defect below lives in behavior, runtime contrast, and viewport, which a static pass cannot see.

**Visual overlays: none.** No browser automation exposed, no chromium/chrome on PATH. No live server started, no injection attempted, no overlay exists. Skipped: rendered screenshots, URL-mode detection, live contrast/hit-target/reflow measurement. All claims come from source reading and the regex detector.

## Overall Impression

The IA is genuinely good and the restraint is real. The problem is that this app has only ever been evaluated on the desktop the product record calls the secondary scene. Every defect that bites only on a small screen, or only at arm's length, has gone unnoticed.

Biggest opportunity: the playing surface knows the exact widest line before it paints. If type size were derived from the character grid instead of the viewport, inviolable alignment becomes the layout engine instead of a thing to defend against.

## What's Working

- **Restraint in the IA.** Four nav controls, four toolbar controls, one job per route. Cognitive-load items 1 and 5 pass cleanly.
- **The `<pre>` is structurally right.** `Tab.vue:76-85` explicitly sets `font-family: monospace`, `letter-spacing: normal`, `line-height: normal`, defending alignment against Pico's inherited `--line-height: 1.5`. The failure is at the viewport level, not the typography level.
- **Progressive disclosure of organization.** Lists and settings behind `<details>` in the nav, never occupying the reading surface.

**Cognitive load: 5 of 8 items fail** (chunking, grouping, visual hierarchy, ≤4 options, working memory). Both bookmark dropdowns render Favorites + every custom list + Create as flat unbounded siblings. `_styles.scss:12-36` scales `--font-size` up with viewport — 16px phone, 20px desktop — so the music-stand device gets the smallest type.

## Priority Issues

### [P0] The playing surface can't fit a tab on the playing device
Widest line in the seed data is 84 characters ("Stand By Me"). At `1.1em` monospace ≈ 1000px on a 390px phone, and the `<pre>` has no `overflow-x`, so the body scrolls sideways. `TabList.vue:27-30` hard-codes `width: 60%; margin-left: 20%` with no media query — a 234px column with 78px dead margin per side, under 120px of dead space.
**Fix:** percentage widths → `width: 100%; max-width: 68ch; margin-inline: auto`; `overflow-x: auto` on the `<pre>`; derive font-size from the widest line so a tab always fills the width exactly. Ship an A−/A/A+ override.
**Command:** `/impeccable adapt`

### [P0] Autoscroll's stop button scrolls off the screen
Under 992px `Tab.vue:50-53` sets the toolbar to `position: inherit` (normal flow) while the window scrolls. The only stop control leaves the viewport within seconds; stopping means scrolling up against something pushing down. No tap-to-pause, no keyboard stop, state signalled by a 4px caret-fill difference.
**Fix:** fixed bottom transport on small viewports, ≥56px target, `env(safe-area-inset-bottom)`; tap-anywhere-on-`<pre>` to pause; real play/pause glyphs with lime active fill; `requestAnimationFrame` accumulator instead of queued `behavior: "smooth"`; honor `prefers-reduced-motion`.
**Command:** `/impeccable shape`

### [P0] A new account crashes to a blank screen on the first tab it opens
`store.getFavoriteslist()` (`store.js:84-90`) is sync but returns the async `createFavoritesList()` — a Promise — when no Favorites list exists. `Bookmarks.vue:45-47` calls `.tabs.find()` on it, throwing during `<script setup>` and taking down the whole `Tab.vue` render. The seeder creates no lists (verified), so this fires for every fresh account. Same shape in `List.vue:10-15` and `Tab.vue:8-9`.
**Fix:** async `getFavoriteslist` awaited behind `v-if`; `createList` awaits `loadLists()` instead of pushing a partial response; normalize `tabs: []`; guard all three lookups with a not-found state; `onErrorCaptured` boundary in `App.vue`.
**Command:** `/impeccable harden`

### [P1] Every failure is silent and every success is unconfirmed
`fetchHelper.js:52-55` rejects on any non-401 failure and no caller has a `try/catch`. A 500 on login leaves `busy = true` and a permanently disabled button. A failed scrape spins forever. A failed save looks like a successful one, and `TabForm` never resets `tab.id` after `addTab`, so Save twice creates a duplicate.
**Fix:** `try/catch` on store calls, `busy` cleared in `finally`, inline banner with Retry; on save, reload from server, take the id from the response, navigate to `/tab/:id`.
**Command:** `/impeccable harden`

### [P1] The brand identity is implemented backwards
Buttons are white on `#a9bc52` = 2.1:1; `.error` is `#c62828` on `#393939` = 2.06:1. Both fail WCAG AA by roughly half. `theme.scss:67` sets `--form-element-background-color: white`, so the nav search and the tab-content textarea are white boxes in a dark app. `--muted-border-color` is near-white `$grey-100` in a dark theme. Surface stack `#393939` page / `#414141` card / `#2c2c2c` nav has the card lighter than the page and the nav darker.
**Fix:** real ramp in `_colors.scss` with a dark `--primary-inverse` (lime must never carry white text); delete the `!important` button override; near-black surfaces with monotonic elevation; error text at ≥7:1.
**Command:** `/impeccable colorize`

### [P2] Search is case-broken and invisible
`MyTabs.vue:10` lowercases the title but not the query — `Stand` matches nothing while `stand` works, and `Stand By Me` is in the seed data. No result count, no clear control, zero-result search renders the same empty div as an empty library.
**Fix:** `.toLowerCase()` on the query, live filtering, "12 of 34" plus a dismissable chip, distinct empty states.
**Command:** `/impeccable onboard`

## Persona Red Flags

**Casey (Distracted Mobile User)** — Blank near-black screen for three serialized API calls on boot, no `<title>` to confirm the right app. 234px library column, 18px card titles. Taps the star mid-song → `Bookmarks.vue:7` `<a href="#" @click>` with no `.prevent` → page jumps to top, verse lost.

**Sam (Accessibility-Dependent)** — `bi-plus-square`, `bi-bookmark-star`, `bi-gear` announce as bare "link" (`alt` invalid on `<a>`/`<button>`, `data-tooltip` hover-only). Four unnamed controls on the tab page. `<dialog :open>` gives no focus trap, no Escape, focusable background; Confirm/Cancel are anchors so Space doesn't activate them. No `aria-pressed` on the autoscroll toggle.

**Jordan (First-Timer)** — Empty `<div>` on first login: no heading, no "add your first tab," no pointer to `+`. Save appears to do nothing → Save again → duplicate. Opens the tab → Favorites Promise bug → blank screen on their first successful action. Finds "Scrape Data" in the gear menu.

**Dana (project-specific: mid-song, tablet on a stand)** — 17.6px type at 70cm because the tablet is under `sm`. 84-column grid unmeasured against the viewport. Stop button left the screen 40 seconds ago. Screen sleeps mid-song — nothing requests `navigator.wakeLock`. No recents, no sort, case-sensitive search.
